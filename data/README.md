# Data folder

| Folder | Contents | In Git? |
|---|---|---|
| `raw/` | `superstore_synthetic_raw.csv` (synthetic input) and `injected_issues.json` (answer key of planted problems) | Yes. Safe because the data is synthetic |
| `processed/` | `superstore_clean.csv`, `rejected_rows.csv` | Yes (small) |
| `processed/star/` | Star-schema CSVs for SQL and Power BI; `ecommerce.db` (SQLite) | No. Rebuilt by the pipeline |

## The data is synthetic
Generated by `python src/generate_synthetic_data.py` (fixed seed 42, so the output is identical every time). It imitates the structure of the well-known "Sample Superstore" file but contains **no real company data**. Never present it as real.

## Using a real dataset instead (not tested in this repo)
1. Download a dataset with a licence that allows your use (for example a Sample Superstore copy), and read its licence. If it is unclear, keep the file out of Git.
2. Put it in `data/raw/` and run (PowerShell):
   ```powershell
   $env:RAW_CSV = "data\raw\SampleSuperstore.csv"
   $env:RAW_ENCODING = "latin-1"     # many copies are not UTF-8; remove if the file is UTF-8
   python src\data_cleaning.py
   ```
3. The cleaner expects these headers: Row ID, Order ID, Order Date, Ship Date, Ship Mode, Customer ID, Customer Name, Segment, Country, City, State, Postal Code, Region, Product ID, Category, Sub-Category, Product Name, Sales, Quantity, Discount, Profit. Dates in `YYYY-MM-DD`, `DD-Mon-YYYY` and `M/D/YYYY` are understood. Edit `COLS` and `DATE_FORMATS` in `src/data_cleaning.py` for other layouts.
4. Section 4 of the data-quality report needs the synthetic answer key and is skipped when `injected_issues.json` is absent. Delete the file when using real data.
5. Then run `build_star_schema.py`, `sql_runner.py`, `reconcile.py`. If a metric in `reconcile.py` is tied to this dataset's structure, it will tell you.
6. If the real file lacks a field (for example no Profit), document the limitation; do not invent the field.
